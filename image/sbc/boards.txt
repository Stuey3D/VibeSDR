# image/sbc/boards.txt — the boards image/sbc/build.sh knows. One line per board, fields separated by spaces;
# everything after the eighth field is the board's display name.
#
# board    the Armbian board id (dl.armbian.com/<board>/) — also the image's file name
# family   Armbian's LINUXFAMILY, as the image's /etc/armbian-release states it (build.sh refuses a mismatch — a wrong
#          guess here costs one decompress, never a wrong card). Boards of one family share the kernel and the root's
#          contents; only U-Boot (outside the partitions) and the device tree differ. See docs/SBC-IMAGES-PLAN.md.
# arch     the Debian architecture of the image (armhf / arm64)
# neon     yes = every SoC of the line has NEON: the build REFUSES an ARMv6 (scalar) /usr/bin/vibeserver on it
# wifi     none | the onboard chip. Decides only what the box does FIRST: with Wi-Fi it raises the open
#          "VibeServer" setup hotspot; without, it waits on Ethernet at vibeserversetup.local:48000. Both always work.
# ram_mb   the smallest RAM the board ships with. ★ A Portable card needs 512 MB (Stuart, 2026-10-25): build.sh refuses
#          less. The 256 MB boards stay on the DietPi ordinary-server image (image/soft66ip-dietpi, v12-soft66ip-image).
# channel  stable = an Armbian "supported" image; community = an Armbian community (trunk) build only
# status   built = a card was built and boot-tested under emulation; planned = next; dietpi = not a Portable (RAM)
#
