VibeServer

Turn an SDR into a network receiver for the VibeSDR apps and any browser.
Current package: __VERSION__ (__ARCH__)

Debian / Raspberry Pi OS

Add the repository once, then it updates with everything else on the machine.

curl -fsSL https://stuey3d.github.io/vibesdr-apt/KEY.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/vibesdr.gpg

echo "deb [signed-by=/usr/share/keyrings/vibesdr.gpg] \
https://stuey3d.github.io/vibesdr-apt stable main" \
  | sudo tee /etc/apt/sources.list.d/vibesdr.list

sudo apt update
sudo apt install vibeserver

Then run vibeserver to configure it (name, location, radio) and sudo systemctl start vibeserver to serve. The service is enabled but not started by the install, on purpose: an unconfigured server that starts itself and fails is a worse first impression than one that waits to be asked.

64-bit only, in practice. The DSP's NEON path is gated on __aarch64__, and a 32-bit userland silently loses all of it — roughly 13× slower on the same hardware.

macOS

A signed, notarised build — download, open, and it runs without a Gatekeeper argument.

Source

VibeServer is built from the VibeSDR tree — the same DSP engine, decoders and protocol the apps use, which is why a fix in one reaches all of them.

github.com/Stuey3D/VibeSDR · GPL-3.0

Packages are signed with ed25519/FC384096D89F0AE7 (VibeSDR Package Signing <packages@vibesdr.net>).
This repository holds build artefacts only; issues and source live in the main repository.
