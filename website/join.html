Join the network

Put your receiver on the VibeServer Network.

A new network, run by the people listening to it. Plug an SDR into a spare Android phone, a Mac or a Linux box, give it a name, and switch on the listing. The server opens a Cloudflare tunnel to the directory by itself.

  • No port forwarding. The tunnel dials out, so nothing opens on your router. Works behind CGNAT.
  • No DDNS. You get a stable name: your-name.vibeserver.vibesdr.net.
  • Your home address stays private. Listeners connect to Cloudflare, never to your house.
  • Real HTTPS, with a real certificate.
AndroidThe app, on a spare phone MacApple Silicon, menu-bar app LinuxRaspberry Pi, arm64 or amd64

Works with an RTL-SDR (V3, V4 or V4L), an Airspy HF+, a HackRF, and on Mac and Linux an SDRplay RSP. All radios are welcome, wideband or locked to one band.

Android

A spare phone becomes a receiver

Any 64-bit Android with USB host. We run one on a 2019 Samsung XCover 4S.

1

Install VibeSDR and plug the radio in

Take the APK from GitHub, or join the Play test group. Connect the dongle with a USB-C OTG adapter and let Android grant the app access to it.

2

Use as server

On the servers list, tap ⇆ Use as server. Give the server a local name, choose the radio, and start it. It is now a receiver on your own network, with its own web page.

3

Say where it is

Under Where this receiver is, enter a Maidenhead locator such as IO92NH. The directory places receivers on a map, and it will not list one without a location. Describing the antenna is optional and helps listeners.

4

Give it a public name and list it

Enter a public name. That name becomes your address on the network. Then switch on List this server publicly. The server opens the tunnel, registers with the directory, and appears at vibeserver.vibesdr.net within a minute.

5

Optional: a PIN, and limits

Set a PIN and only people you give it to can listen. The settings are behind the admin password either way. Session limits, cooldowns and bans are on the same page.

Mac

A menu-bar app around the same engine

Apple Silicon. Notarised, so it opens cleanly.

1

Download and open VibeServer

Get the latest VibeServer for macOS from the releases page and plug the radio in. RTL-SDR and Airspy HF+ need nothing extra. For an SDRplay RSP, install SDRplay's own API first.

2

Name it and open it

Give the receiver a name, choose the radio, and click Open in Browser. That is the receiver: waterfall, audio, decoders, and the same page the apps talk to.

3

List on VibeSDR.net

Open Settings… from the menu bar and switch on List on VibeSDR.net. Give it a public name and a locator if it asks. Off by default. Nothing is published until you switch it on.

Linux

A Pi, an old laptop, a NUC, a home server

Debian, Ubuntu and Raspberry Pi OS, arm64 or amd64, 64-bit only. Tested on Debian 13 and Ubuntu 24.04. Other distributions are likely to work but are unverified.

1

Install from apt

The same block on ARM and on Intel/AMD. Everything VibeServer needs comes with it.

curl -fsSL https://apt.vibesdr.net/KEY.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/vibesdr.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/vibesdr.gpg] https://apt.vibesdr.net stable main" \
  | sudo tee /etc/apt/sources.list.d/vibesdr.list
sudo apt update
sudo apt install vibeserver

Log out and back in. The install adds you to the plugdev group so the radio opens without root, and that only takes effect on a new login.

2

Run the wizard

vibeserver

A short text wizard: it asks which radios to serve and for an admin password, then enables and starts the service for you. Everything else, the name, the location and the listing, is done on the web page in the next steps.

3

Open the receiver and its setup page

Browse to http://<the address the wizard printed>:48000. On the same network http://vibeserver.local:48000 usually works. The splash screen has a SETUP button. It asks for the admin password.

4

Advertise on VibeSDR.net

On the setup page, give the receiver a name and fill in Where this receiver is with a Maidenhead locator. Then under Advertise on VibeSDR.net, enter a public name and switch on List this server publicly. Save. The tunnel opens and the listing appears within a minute.

5

Bring the gain up

A new install starts the radio at minimum gain, on purpose. Open the menu in the receiver and raise it until the noise floor lifts. What you set is remembered.

If you have an SDRplay RSP, apt cannot fetch SDRplay's driver for licensing reasons. The apt page has the three lines to install it.

Your radio, your rules.

VibeServer can serve a radio in three shapes, so you decide what listeners get.

Single userOne listener at a time. The radio is theirs while they have it: any frequency, any mode, any decoder. Like a SpyServer.
Shared VFOOne tuner, one decoder, many listeners. Everyone hears the same station and sees the same live waterfall. Like an FM-DX server, with a waterfall.
Locked rangeA fixed window, independent tuning. Several people tune as they please inside a range you set. Like an OpenWebRX profile.

On top of the shape you choose, you can allow or block frequencies and bands, allow or block demodulators and decoders, cap the gain, or lock it entirely.

Club, friends and family. Want to list the receiver but not open it to everyone? Set a PIN and only people you give it to can connect. The settings sit behind the admin password either way, and you can take a radio back from any device.

Raw IQ out, if you want to offer it. Switch Raw IQ out on in the server settings and listeners can take the raw IQ of the channel they are tuned to into their own apps through VibeIQ, as rtl_tcp on their machine. 48 kHz through the tunnel, up to 250 kHz on your network, or the radio's full bandwidth when it has one listener (Trunk Recorder wants that). Off by default, and you can offer it on the local network only.

It shares its toys. On Linux, VibeServer can release the radio when nobody is listening so another program can use it. Handy if a decoder wants the dongle between sessions.

Listeners' addresses are visible to you, as on every SDR receiver on the internet. That is how session limits and block lists work. Yours is never published.
